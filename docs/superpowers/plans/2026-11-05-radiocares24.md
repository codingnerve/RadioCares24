# RadioCares24 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship radiocares24.com as a visually distinct sibling of radiosatscare: new brand, light/friendly design, symptom-first home page, rewritten copy, same reliable enquiry plumbing.

**Architecture:** `C:\Project\radio\radiocares24` is already a copy of radiosatscare (app, server, lib, tests, deploy). Keep `server/`, `lib/enquiry-schema.ts`, `lib/seo.ts` helpers, the enquiry form logic and the test suite. Replace the design system (`globals.css`), shell components, home page, inner-page templates and copy. Only `lib/content.ts` holds page copy; only `lib/site.ts` holds site config.

**Tech Stack:** Next.js 16.4 (App Router), React 19, Tailwind 4 (`@theme` tokens in `app/globals.css`), TypeScript, zod, Vitest, `@fontsource-variable/*`.

**Spec:** `docs/superpowers/specs/2026-11-05-radiocares24-design.md`

## Global Constraints

- Read `node_modules/next/dist/docs/` for any Next API you are unsure of (AGENTS.md: this Next has breaking changes).
- Brand: **RadioCares24**, tagline "Friendly help for your car's satellite radio", domain `https://radiocares24.com`.
- Palette: cream `#fbf6ec`, teal `#0e5a57` (text/surfaces; darker `#083f3d`), coral `#ff6a4d` (buttons, dark text `#2a0f08` on it), coral text-safe `#b8331a`, muted text `#3f5a58`. Guide accents (surface / ink): sage `#dff0e0`/`#1f6b3a`, sky `#dcecf8`/`#1d5d8f`, butter `#fbefc6`/`#7a5600`, blush `#fbdcd6`/`#a3402d`.
- Fonts: `@fontsource-variable/bricolage-grotesque` (headings, family "Bricolage Grotesque Variable"), `@fontsource-variable/dm-sans` (body, "DM Sans Variable"). Remove Inter and Manrope.
- Shapes: radii 24-32px on cards, pill buttons (`rounded-full`), floating pill header, floating mobile call pill. No navy, no orange, no thin ring decorations.
- No "24/7", no hours, no ratings, testimonials, guarantees or provider logos. Hours only render from `NEXT_PUBLIC_SUPPORT_HOURS`.
- Every page shows the independence statement (footer plus hero/banner note): not the provider, never asks for card numbers or passwords.
- All contact details (phone, email, hours, legal name, address, jurisdiction) come from env; blank means the UI for it is hidden. Do not reuse radiosatscare's Okemos address.
- AA contrast, visible focus ring (coral outline), 44px touch targets, `prefers-reduced-motion` respected, mobile 360px wide with no horizontal scroll.
- Production port 3401. radiosatscare is never modified.
- Do not run `git commit` unless the user asks; leave changes in the working tree.

## Review Focus

1. All contact env vars blank: no "Call " with empty number, no empty address block, no mobile call pill, no extra bottom padding on `<main>`.
2. `NEXT_PUBLIC_SITE_URL` unset: canonical, sitemap, Open Graph and the default CORS origin all resolve to `https://radiocares24.com`.
3. No leftover "RadioSatCare"/"radiosatscare" anywhere in source, emails, structured data, deploy files or metadata.
4. Symptom picker works without JS and by keyboard (tiles are real links with visible focus).
5. 360px viewport: floating header, mobile menu, call pill and the enquiry form never overlap or overflow horizontally; the call pill hides while a form field is focused.
